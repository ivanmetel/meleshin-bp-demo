# Машина сборки КП — демо модели реализации

Демонстрация работы машины автоматической сборки коммерческого предложения (КП / BP) по ТЗ [BP auto-assembly](https://github.com/ivanmetel/meleshin-os) (раздел `_PM`, 30.09.2026): оператор заполняет манифест — машина собирает документ, считает арифметику и проверяет ворота.

**Смотреть демо: <https://ivanmetel.github.io/meleshin-bp-demo/>**

Все данные демо вымышлены: объект 2699-Limassol-Apartment, суммы, участники и контакты не существуют. Демо собирается целиком в браузере, без сервера; правки манифеста живут в памяти страницы до перезагрузки.

## Модель

```
манифест (оператор)  →  машина (агрегация · арифметика · маршрут блоков · ворота 1–10)  →  документ (слайды + markdown)
```

- Оператор ничего не перепечатывает: манифест — указатели на источники (карточка объекта, строки сметы, файлы фото) плюс коммерческие значения Ивана и переключатели макета.
- Машина не сочиняет текст: каждая фраза документа — либо фиксированный блок шаблона, либо значение из источника.
- Один факт — один носитель: состав работ живёт только в таблице работ; ворота 9 проверяют это механически.

Кабинет клиента (утверждённая версия по решениям Ивана, ТЗ §13): статус «Отправлен / Согласован с клиентом», кнопка согласования, таблица работ.

## Клиентская смета

Вид «Смета» повторяет структуру клиентского бюджета (Google-таблица): **сверху два экрана-переключателя — «Работы» и «Материалы» (нажаты по одной или обе, кнопки «Все» нет), слева у сметы — вертикальный список помещений: Все · Зал · Кухня · Санузел · Спальня 1 · Спальня 2** (заголовок списка — на уровне названия блока); оба экрана нажаты → оба блока рядом (~60% / ~40%):

- блоки «Строительно-монтажные и отделочные работы» и «Материалы», в шапке каждого справа — сумма без подписи: название блока уже говорит, что суммируется;
- таблица: # · Работа/Материал · Ед. · Кол&#8209;во · Цена за ед., € · Стоимость, € · Доп. инфо — без столбца «Помещение» (помещение выбирается в списке слева); заголовки — в одну строку; ширины: имя — гибкая колонка, числовые — по заголовку, «доп. инфо» — остаток, числа не переносятся; «Стоимость» — только цифры; € — только в заголовках колонок и итогах шапки, ячейки без знака; «доп. инфо» — последняя колонка, слот из источника, показывается только когда несёт факт, которого нет в колонках строки;
- тёмная панель (градиент #2B2826→#3D3734, виньетка, приглушённые заголовки колонок, подсветка строки) — утверждённое UI-решение;
- выбор помещения разворачивает агрегированные строки обратно по помещениям, нумерация с 1; итог в шапке блока — итог текущего выбора (сумма без подписи);
- сохранение для клиента — «Сохранить PDF» (печать браузера; в производственной машине — marp-cli), выгрузки markdown нет.

Кабинет показывается на русском; язык кабинета клиента — тумблер в админ-манифесте (вид «Манифест», раздел «Решения ТЗ §12»): ru активен, en — `[ ]` (решение 2 ТЗ). Фирменный шрифт Involve в веб-демо заменён на Inter/Manrope.

## Что реализовано

- Реестр 22 блоков, фиксированный маршрут зон ТЗ §5, обязательные и опциональные блоки.
- Агрегация строк сметы по «имя + цена» (одна работа с разными ценами не склеивается), сплошная нумерация, разбивка таблицы по 12 строк на страницу с повтором заголовка, «Итого» на последней странице.
- Арифметика: строка = кол-во × цена; «Итого» = Σ; цена = Итого + сопутствующие + черновые материалы. Формат ru: пробел тысяч, запятая, 2 знака.
- Варианты: наложение на базовый состав — замена/исключение строк (в демо — перегородки: «Газоблок», «Без перепланировки»; производственный приём — семейство 2636), пересчёт итогов и строки цены, суффикс в имени файла.
- Ворота 1–10 ТЗ §9, включая скан повторов и проверку утечки YYNN в клиентские поля.
- Клиентская смета: два экрана-переключателя, вертикальный список помещений, тёмная панель по UI-спеке, итоги текущего выбора в шапках блоков.
- Решения ТЗ §12 как переключатели: бренд, блок согласований, позиция менеджера, язык кабинета клиента (админ-тумблер); манифест — поля без степперов, срок — выбор недель/дней/месяцев. en-профиль и рендер PDF — за рамками демо `[ ]`.
- Эмиттер markdown-файла КП (Marp frontmatter, блоки, таблицы) — просмотр; выгрузки md нет, клиент сохраняет PDF.

## Запуск

Демо уже опубликовано — открывать в браузере: **<https://ivanmetel.github.io/meleshin-bp-demo/>** (GitHub Pages этого репозитория, обновляется при каждом push).

Локально (для правок рабочей копии): статические файлы, любой локальный сервер —

```
python3 -m http.server 8080
# http://localhost:8080
```

## Файлы

| Файл | Назначение |
|:--|:--|
| `index.html` | каркас кабинета (топбар, герой, сайдбар, контент) |
| `styles.css` | стили кабинета: палитра, тёмная панель сметы, таблицы |
| `data.js` | фиксированные блоки ТЗ (дословно), демо-строки работ и материалов, манифест по умолчанию |
| `app.js` | машина: варианты, агрегация, сборка, ворота, эмиттер markdown + интерфейс |
